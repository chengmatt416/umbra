    03安全閘門與核准 Safety gate & approvals

    Safety gate (every action) 安全閘門：每個動作都經過

    操作／狀態說明類型往外的關係（→ 目標：關係類型，說明）
    Agent asks for an actionhost tool 或 omp 的工具呼叫入口／畫面／顯示
    • → Risk classifier：觸發／導向，分類
    Risk classifier分類：風險類別與等級；自我保護檢查／政策／判斷
    • → Approval policy：觸發／導向，依模式判斷
    Approval policyCautious / Balanced / Autonomous；禁止類別檢查／政策／判斷
    • → Allowed → performed：觸發／導向，不需核准
    • → Remembered rules (this session)：觸發／導向，先看記住的規則
    • → Denied → not performed：阻擋／封鎖，禁止類別／自我保護
    • → Ask the user：觸發／導向，需要核准
    Remembered rules (this session)本工作階段記住的規則；CRITICAL 永不預先核准檢查／政策／判斷
    • → Allowed → performed：觸發／導向，符合規則
    Allowed → performed直接執行使用者操作（沒有往外的關係；由其他節點指向它）
    Denied → not performed不執行；告知代理原因，不重試阻擋／危險／封鎖（沒有往外的關係；由其他節點指向它）
    Ask the user送出核准請求（5 分鐘逾時）檢查／政策／判斷
    • → Approve once：觸發／導向，核准一次
    • → Approve + remember：觸發／導向，核准並記住
    • → Deny (with reason)：觸發／導向，拒絕
    • → No answer in 5 minutes：觸發／導向，5 分鐘無回答
    • → Session stopped → cancelled：觸發／導向，工作階段停止
    • → WAITING_APPROVAL：改變／影響，進入 WAITING_APPROVAL
    • → Inbox list：改變／影響，待審批數量
    • → Capsule expanded：改變／影響，待審批卡片
    • → Approve：改變／影響，核准通知
    • → Wait graph：改變／影響，等待邊
    • → Wait graph：改變／影響，核准等待也是等待邊

    Approval answers 核准的回答方式

    操作／狀態說明類型往外的關係（→ 目標：關係類型，說明）
    Approve once只核准這一次使用者操作
    • → Input gate：觸發／導向，放行（僅此一次）
    • → Approval ledger (approvals.jsonl)：改變／影響，寫入紀錄
    Approve + rememberThis app / This command / This category（本工作階段）使用者操作
    • → Remembered rules (this session)：改變／影響，記住規則（本工作階段）
    • → Input gate：觸發／導向，放行
    • → Approval ledger (approvals.jsonl)：改變／影響，寫入紀錄
    Deny (with reason)拒絕並說明原因使用者操作
    • → Denied → not performed：觸發／導向，不執行，告知代理
    • → Approval ledger (approvals.jsonl)：改變／影響，寫入紀錄
    No answer in 5 minutes逾時 → 未執行（失敗封閉）阻擋／危險／封鎖
